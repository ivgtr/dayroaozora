# 読書クライアントの設計

サービスの特徴は [README](../README.md) を参照。

## 本文の取得

サーバーは上流の作品情報と本文を同じ応答から受け取り、本文を構造化してブラウザへ渡す。旧API応答との互換性を保ち、`delivery` の検証状態と本文識別子を伝達する。

本文受信中の通信断・タイムアウトと、受信後のJSON・内容検証失敗を区別する。既知の提供停止コードを優先し、コードのない429・502・503・504は一時障害として扱う。

## 保存本文と再検証

IndexedDBに本文を保存し、旧形式を読みながら新形式で保存する。正常な保存本文はオフラインや一時障害で利用できる。保存失敗だけで取得済み本文を表示できなくしない。

オンラインで作品を開く際、未検証または検証期限を過ぎた本文を再検証する。検証期限は上流の検証日時を基準とし、閲覧・CDNヒット・旧版提供・失敗によって延長しない。ブラウザの再検証間隔は24時間。未閲覧・オフラインの端末へ訂正を即時反映する保証はない。

不存在・権利停止・提供停止・内容不正を検知した本文は無効化し、次回オフラインでも再利用しない。本棚・読了履歴は保持する。

## 本文と読書位置

`readingContentId` は本文の識別子と構造化処理の版を組み合わせる。作品を開く際に保存位置の識別子と比較し、版が異なる場合や片方だけが未識別の場合は読書位置を先頭に戻す。お気に入り・読了履歴・累積記録は保持する。

表示を開始した読書セッションでは本文を固定し、背景で取得した訂正版へ差し替えない。

## 先読みと配信

今日の本文表示が成功した後、翌日1作品を先読みする。失敗で通常閲覧を止めず、同日・同作品への反復を抑える。サーバー設定 `PREFETCH_ENABLED=false` で先読みを停止でき、先読み要求には204を返す。

本文読込みには全体の期限を設ける。正常な検証済み本文のCDN保持は1時間、旧版・未検証・エラーは `no-store` とする。配信設定の変更時には、既存CDN応答の失効も確認する。
